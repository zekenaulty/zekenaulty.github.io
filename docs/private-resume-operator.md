# Private résumé operator: independent cloud execution

Follow-up to PR #2 at `661babb44c9c8c81f17b09ae5985a3baa8bc5f81`. This adds diagnostics and retained offline evidence, not a hosted adapter or public build change. See [the version 1 service contract](private-resume-tool.md) for request fields and limits.

## Smallest executable path

Use a trusted cloud checkout of the reviewed commit, Node 20.19+ or 22.12+ (tested with Node 24), and `npm ci --ignore-scripts`. The lockfile installs `dotenv`, `docx` and `pdfkit`, used by the private service/export path. Node supplies fetch; there is no provider SDK dependency. No React server, Vite build, browser, Wrangler login, public Worker, or deployment is needed for the stdin CLI.

Run `node scripts/resume-operator.js preflight` before arranging private inputs. Its `ok` means only runtime/dependency resolution and canonical catalog loading passed. It does not inspect credentials, enumerate private inputs, change permissions, or create directories. It does not certify truthful/current career claims, contact completeness, job readiness, cloud persistence, provider access, or live-generation readiness. Dependency resolution is not execution proof; run the smoke command next.

Run `node scripts/resume-operator.js smoke` for the offline service proof. Prefer a clean process environment: on POSIX, `env -i PATH="$PATH" node scripts/resume-operator.js smoke`. No credential variable is needed or consulted. This calls the importable service, **not stdin CLI generation**. The only provider transport is an injected deterministic mock with a dummy credential; unexpected default fetch calls throw. There is no live mode. This is application-level transport isolation, not an OS network sandbox.

The command creates a new owner-only temporary fixture workspace, prints its `evidencePath`, and intentionally retains it, including synthetic JD, selected draft, and HTML/TXT/DOCX/PDF. Never use these test exports as applications: the unchanged renderer includes its public identity heading, but all supplied role text is conspicuously synthetic. It never loads the user's ignored private corpus or credential files. It records stage outcomes, source/input/draft/export SHA-256 hashes, source commit, lockfile/script hashes, and mock call count. Draft timestamps and document metadata mean artifact hashes vary across runs; deterministic selection does not mean byte-identical archives.

Each run proves empty-state discovery, missing-job rejection, `list_jobs → prepare → generate → validate → export`, explicit-network/hash gates, draft/export no-overwrite and tamper rejection. Export signatures and nonempty bytes are checked; this is not visual layout, DOCX text extraction, PDF text extraction or ATS parsing verification. The existing `npm run check:resume-tool` remains the broader regression suite for source changes, unsafe paths, malformed responses, refusal, timeouts and retry behavior. The smoke adds retained operator evidence rather than replacing those assertions. An error exits nonzero and retains a partial manifest when the fixture directory and evidence file remain writable, without raw provider errors or private text. Setup or evidence-write failures may prevent retention.

Temporary storage is not a backup. Keep the manifest plus artifacts together only in an explicitly approved private durable destination if preservation is required. No upload or synchronization is implemented here. Generated files are intentionally excluded from Git/public builds. Do not post real private manifests or artifacts in a public PR. The command does not accept a destination path, overwrite an existing proof directory, or clean up prior evidence automatically.

## Capability and dependency inventory

- **Checked-out canonical source:** tracked `src/data/resume/` modules supply the catalog, chronology and exact selectable text. Git reproduces that revision, not later private corrections or verified career evidence. Source hashes detect drift, not truth. Confirm facts/contact details separately before employer-facing use.
- **Job discovery:** `list_jobs` only lists local `.md`/`.txt` inputs. It does not search job boards, triage opportunities, track applications, or obtain private inputs remotely.
- **Preparation:** `inspect_job` reads a selected private JD; `prepare` checks it and returns source/input hashes, destination, request byte size and configuration without loading credentials or making a provider request. Keep these results private when using real inputs.
- **Generation:** one explicitly authorized provider call selects canonical references. A secure existing Node runtime credential must be injected for that process. A Worker secret and Cloudflare/Wrangler authentication are not this credential. Do not read back, recreate, log, or put a key in source/CLI arguments/browser code. Provisioning reported elsewhere does not prove injection, model access or billing readiness; these diagnostics deliberately leave that status unverified.
- **Validation/export:** saved private selection, matching canonical source and returned draft hash permit local validation and four-format export without more provider calls. No server or deployment is required. Human review remains mandatory; successful integrity checks do not approve claims or authorize submission.
- **Private state:** ignored `private/job-descriptions/`, `private/resume-profiles/`, and `private/resume-exports/` belong to the user, not the Git checkout. A fresh cloud clone has no guarantee of these files. The fixture proof establishes only synthetic operation, not availability of the user's JDs, archived drafts or exports.
- **Missing collaboration functions:** no shared authentication, durable review/approval ledger, automatic private sync, job-board discovery or application submission. A separately authenticated stateful adapter can follow later; anonymous public `/chat` must remain separate.

## Private-state operating agreement before real execution

Choose one authoritative private workspace and owner-approved backup destination. The user owns the corpus; Crom operates only within granted access. Obtain explicit authorization naming inputs, destination and purpose before transferring private material. Do not assume Git or a connected cloud computer supplies persistence. Verify retention/restart behavior and a backup/restore exercise before calling the workspace durable.

Use immutable revision IDs and a single writer for each draft. Preserve original recovered drafts byte-for-byte as archives. Record source commit/catalog hash, JD hash, input configuration/hash, draft hash, export hashes and review state privately. Hashes are integrity aids, not signatures or proof of author approval. Never silently merge competing JSON drafts or overwrite exports. Copy conflicts as separate revisions, compare provenance, and let the owner select/review. Restore source revision and matching private inputs/artifacts together, then revalidate. Review stale locks and uncertain billed outcomes before retrying; do not blindly delete locks or regenerate.

## Transition from offline proof to one real job

1. Verify the reviewed checkout and dependencies with preflight and smoke. Retain the proof manifest privately; use the existing JSON CLI `list_jobs` for actual discovery only in the intended private workspace.
2. Explicitly provision one authorized real JD and the agreed private-state/recovery arrangement. Inspect privately and run `prepare` for a fresh revision ID. Record the actual returned hashes/configuration, not fixture hashes.
3. Confirm provider, selected JD plus canonical data sharing, model, reasoning, token cap and monetary limit before a live call. Secure injection may already exist; do not create another key as a substitute for checking authorization. `allowNetwork: true` and a matching `expectedInputHash` are technical gates, not consent or a spending cap. Defaults are one attempt, 120-second timeout, 12,000 output tokens; accepted output limits are 1,024–16,000. Input limits are 48,000 JD bytes and 160,000 serialized request bytes. Token caps do not bound total money; check current prices and account limits. No automatic retry or fallback.
4. Only after explicit authorization, run one `generate` with the exact prepared inputs. Live model availability, structured-output compatibility, usage/billing and quality remain unverified by this increment. Record status and numeric usage privately, not secrets or raw provider errors in public reports.
5. Run `validate`, then `export` with its exact draft hash. Review facts, omissions, chronology, contact completeness, rendered pages and extracted text. Keep durable owner approval separate from generation. No publishing, employer contact or application submission follows automatically.
